# HTMLforPDF

A service for generating PDFs from URLs using [Playwright](https://playwright.dev/). Supports synchronous generation (direct response) and asynchronous generation via RabbitMQ queue with webhook delivery.

## Prerequisites

- **Node.js** >= 24
- **RabbitMQ** (for asynchronous generation via queue)
- **Playwright browsers** (run `npx playwright install chromium --with-deps` outside Docker)

## Installation

```bash
git clone <repo-url>
cd HTMLforPDF
npm install
```

## Environment Variables

Create a `.env` file in the project root:

```env
PORT=3000
API_KEY=<random-secret-with-at-least-32-characters>
RABBITMQ_URL=amqp://localhost
PDF_QUEUE_NAME=html_for_pdf_job_v2
WORKER_CONCURRENCY=1
```

| Variable             | Default               | Description                          |
| -------------------- | --------------------- | ------------------------------------ |
| `PORT`               | `3000`                | HTTP server port                     |
| `RABBITMQ_URL`       | `amqp://localhost`    | RabbitMQ connection URL              |
| `PDF_QUEUE_NAME`     | `html_for_pdf_job_v2` | RabbitMQ queue name                  |
| `WORKER_CONCURRENCY` | `1`                   | Number of jobs processed in parallel |

## API Routes

Base path: `/api/pdfs`. Required header: `X-API-Key: <API_KEY>`.

---

### `POST /api/pdfs/`

Generates a PDF **synchronously** and returns the file in the response.

#### Request Body

```json
{
  "url": "https://example.com",
  "options": {
    "format": "A4",
    "landscape": true,
    "margin": { "top": "2cm", "bottom": "2cm" }
  }
}
```

| Field     | Type     | Required | Description                              |
| --------- | -------- | -------- | ---------------------------------------- |
| `url`     | `string` | ✅       | URL of the page to convert to PDF        |
| `options` | `object` | ❌       | PDF generation options (see table below) |

#### Responses

| Status | Content-Type       | Description                       |
| ------ | ------------------ | --------------------------------- |
| `200`  | `application/pdf`  | Generated PDF file                |
| `422`  | `application/json` | Validation error (invalid fields) |
| `500`  | `application/json` | Internal error                    |

**422 error example:**

```json
{
  "errors": [{ "field": "url", "message": "The url field must be a valid URL", "rule": "url" }]
}
```

---

### `POST /api/pdfs/jobs`

Queues PDF generation **asynchronously**. The PDF will be generated by the worker and sent to the provided webhook URL.

#### Request Body

```json
{
  "url": "https://example.com",
  "webhookUrl": "https://my-server.com/webhook/pdf",
  "options": {
    "format": "A3",
    "printBackground": true
  }
}
```

| Field        | Type     | Required | Description                                      |
| ------------ | -------- | -------- | ------------------------------------------------ |
| `url`        | `string` | ✅       | URL of the page to convert to PDF                |
| `webhookUrl` | `string` | ✅       | URL that will receive the generated PDF via POST |
| `options`    | `object` | ❌       | PDF generation options (see table below)         |

#### Responses

| Status | Description                                                           |
| ------ | --------------------------------------------------------------------- |
| `202`  | `{ "status": "queued", "jobId": "<uuid>" }` — Job queued successfully |
| `422`  | Validation error                                                      |
| `500`  | Internal error                                                        |

---

### PDF Generation Options (`options`)

All fields below are **optional**. Default values applied: `format: "A4"` and `printBackground: true`.

| Field                 | Type               | Description                                                       |
| --------------------- | ------------------ | ----------------------------------------------------------------- |
| `scale`               | `number`           | Rendering scale (between `0.1` and `2`, default: `1`)             |
| `displayHeaderFooter` | `boolean`          | Display header and footer in the PDF                              |
| `headerTemplate`      | `string`           | HTML template for the header                                      |
| `footerTemplate`      | `string`           | HTML template for the footer                                      |
| `printBackground`     | `boolean`          | Print background graphics (default: `true`)                       |
| `landscape`           | `boolean`          | Landscape orientation                                             |
| `pageRanges`          | `string`           | Page ranges (e.g., `"1-5, 8"`)                                    |
| `format`              | `string`           | Paper format (default: `"A4"`)                                    |
| `width`               | `string \| number` | Custom width (e.g., `"8.5in"`, `100`)                             |
| `height`              | `string \| number` | Custom height (e.g., `"11in"`, `200`)                             |
| `margin`              | `object`           | Margins: `{ top, right, bottom, left }` (e.g., `"1cm"`, `"10px"`) |
| `preferCSSPageSize`   | `boolean`          | Use page size defined via CSS `@page`                             |
| `tagged`              | `boolean`          | Generate PDF with accessibility tags                              |
| `outline`             | `boolean`          | Generate outline/bookmarks from headings                          |

**Accepted `format` values:** `Letter`, `Legal`, `Tabloid`, `Ledger`, `A0`, `A1`, `A2`, `A3`, `A4`, `A5`, `A6`

**Accepted units for `width`, `height`, and `margin`:** `px`, `in`, `cm`, `mm`

**Available classes for `headerTemplate` and `footerTemplate`:**

| Class        | Injected value        |
| ------------ | --------------------- |
| `date`       | Formatted date        |
| `title`      | Document title        |
| `url`        | Document URL          |
| `pageNumber` | Current page number   |
| `totalPages` | Total number of pages |

## Webhook

When a job is processed by the worker (via `POST /api/pdfs/jobs`), the generated PDF is sent via **POST** to the provided `webhookUrl`.

### Request Format

- **Method:** `POST`
- **Content-Type:** `multipart/form-data`
- **File field:** `file`
- **Filename:** `file.pdf`
- **MIME type:** `application/pdf`

### Equivalent cURL Example

```bash
curl -X POST https://my-server.com/webhook/pdf \
  -F "file=@file.pdf;type=application/pdf"
```

### What Your Webhook Endpoint Should Expect

Your server should accept a `POST` request with `multipart/form-data` containing a `file` field with the PDF binary. Example using Express:

```typescript
import multer from 'multer';

const upload = multer({ dest: 'uploads/' });

app.post('/webhook/pdf', upload.single('file'), (req, res) => {
  console.log('PDF received:', req.file);
  res.sendStatus(200);
});
```

> **Note:** The worker considers the delivery successful when the webhook returns an HTTP `2xx` status. Any other status will be logged as an error.

## Security and deployment changes

Use Node.js 24 or newer. Install dependencies with `npm ci`, then run
`npm run build` before `npm start` or `npm run worker`. Development commands
continue to run TypeScript directly. Runtime imports are native ESM; no import
rewriting script is needed.

Copy `.env.example` to `.env` and set `API_KEY` to a random secret of at least
32 characters (`openssl rand -hex 32`). Every PDF request must include
`X-API-Key: <your secret>`. The API fails startup without a valid key.
Terminate TLS at your gateway and keep the key out of client-side applications.
The shared key is intended for service-to-service access; separate tenant keys,
quotas and authorization belong at the gateway if multiple tenants use the API.

Only public HTTP/HTTPS destinations on ports 80 and 443 are accepted. Credentials
in URLs, private/reserved IPv4 and IPv6 addresses, and DNS results containing
private addresses are rejected. This also applies to webhook URLs. Browser
traffic uses a per-render forward proxy that connects to validated IP addresses,
so redirects and subresources cannot bypass the check by rebinding DNS.
Service workers, downloads and WebSockets are disabled. Webhook redirects are
rejected rather than followed. Internal dashboards and localhost webhooks are
therefore no longer supported.

Renderers use isolated browser instances with Chromium sandboxing, a total render
deadline, a network byte budget and a concurrency limit. `MAX_PDF_BYTES` is checked
after PDF generation; container memory/CPU/PID limits remain necessary to bound
resource use while Chromium renders or decompresses content. The network budget
counts received HTTP body bytes or encrypted HTTPS tunnel bytes, rather than
expanded page memory. Keep an outbound firewall policy as an additional boundary,
particularly against a compromised browser. Do not disable Chromium's sandbox to
work around host restrictions: enable unprivileged user namespaces on a suitable
host. The Compose seccomp profile is adapted from Microsoft's Playwright project
(`utils/docker/seccomp_profile.json`) and allows the namespace syscalls Chromium
needs, plus `chroot` inside its user namespace while the outer container drops
all capabilities. Kernel capability checks still apply. The containers run as `node`, without added capabilities, with a read-only
filesystem and temporary writable storage.

Docker builds do not receive RabbitMQ credentials or copy `.env` files. Supply
credentials at runtime, preferably using your deployment secret manager. Both
images compile TypeScript in a build stage and install production dependencies
with `npm ci`. RabbitMQ remains an external dependency; use restricted broker
credentials and `amqps://` where the broker is reached across a network.

### Queue migration and delivery

The default queue is now `html_for_pdf_job_v2`. The main queue is bounded and has
`<queue>.retry` and `<queue>.dead` companion queues. Existing queues with different
arguments cannot be redeclared: drain existing jobs using the previous worker,
then move both API and worker to the new queue name. Old messages lack the required
UUID `jobId` and should not be copied unchanged into the new queue. Do not delete
existing queues containing jobs. Queue names and limits must match between API
and worker.

The API returns `202` with `{ "status": "queued", "jobId": "<uuid>" }` after a
publisher confirmation. A job is acknowledged only after successful webhook
delivery or confirmed publication of its retry. Failed jobs are retried after
30 seconds, up to `JOB_MAX_ATTEMPTS` total attempts, and then dead-lettered.
Malformed jobs go directly to the dead-letter queue. The worker reconnects after
connection/channel failures. Monitor the dead-letter queue and replay jobs only
after addressing the failure. Dead-letter queues are bounded and can fill: monitor
capacity. Classic RabbitMQ dead-letter transfers are not a transactional delivery
guarantee during broker failures; production installations requiring stronger
broker guarantees should use a supported quorum-queue topology and at-least-once
dead-lettering policies.

Delivery can repeat if the worker crashes after the receiver accepts the webhook
but before the acknowledgement. Webhooks include `X-Job-Id` and
`Idempotency-Key`; receivers must persist processed IDs and deduplicate deliveries.
Submitting the same API request twice creates two jobs. This service does not
provide an exactly-once guarantee, persistent job status endpoint, or an archive
of generated PDFs. A retry renders the source again, which may have changed.

Set `WEBHOOK_SECRET` to sign deliveries with HMAC-SHA256. The hex signature in
`X-Webhook-Signature` covers `timestamp + "." + jobId + "."` followed by the raw
PDF bytes, using `X-Webhook-Timestamp` and `X-Job-Id`. Verify against the extracted
file bytes, compare signatures in constant time, reject old timestamps, and
record job IDs before applying side effects.

### Operational controls

See `.env.example` for render/webhook deadlines, PDF/network size limits, queue
capacity, retry count and concurrency settings. `RATE_LIMIT_PER_MINUTE` limits
PDF requests per source IP per API process, including unauthenticated attempts.
When deploying behind a reverse proxy, configure rate limits at the gateway;
the application deliberately does not blindly trust `X-Forwarded-For`. Distributed
quotas must be enforced by shared infrastructure. `WORKER_CONCURRENCY` controls
prefetch; keep it at or below `MAX_CONCURRENT_RENDERS` for the worker.

`GET /health/live` checks API process liveness. `GET /health/ready` requires the
API key and checks RabbitMQ connectivity/topology. Rendering still depends on a
working Chromium sandbox and external connectivity; monitor render failures as
well. Logs are JSON with request/job IDs and redaction of sensitive fields.
Graceful shutdown stops intake and allows in-flight processing to finish within
a bounded deadline.

Validate with `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`,
and `npm audit`. Tests cover network destination policy, proxy blocking, browser
cleanup/timeouts/concurrency, queue acknowledgements/retries, API authentication,
validation, and webhook signing. For Docker, run `docker compose up --build` after
configuring `.env` and the external broker.
